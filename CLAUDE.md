# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

PostLuma is a mailbox service that runs entirely on Cloudflare (Workers + Email Routing + D1, optional R2), deployed in one of two service modes (`SERVICE_MODE`): `personal` (the administrator's own mailbox) or `temporary` (a multi-user temporary-mail service). Design: [docs/MODES_DESIGN.md](docs/MODES_DESIGN.md). Product requirements: [docs/PRD.md](docs/PRD.md) (Chinese). Phased roadmap and open product questions: [docs/DEV_PLAN.md](docs/DEV_PLAN.md) — check it before starting a feature and tick items off when done.

## Commands

```bash
npm run dev                 # Vite + Workers runtime (workerd) locally; API, SPA and bindings in one server
npm run db:migrate:local    # apply migrations/ to the local D1 (.wrangler/state) — needed before first `dev`
npm test                    # Vitest inside workerd (@cloudflare/vitest-plugin)
npx vitest run test/health.test.ts      # single file
npx vitest run -t "reports the database" # single test by name
npm run test:e2e            # Playwright against the dev server on throwaway state (.wrangler/e2e); browsers: npx playwright install chromium
npm run type-check          # vue-tsc --build over all three tsconfig projects
npm run build               # type-check + vite build -> dist/client (SPA) + dist/postluma (Worker)
npm run cf-typegen          # regenerate worker-configuration.d.ts after editing wrangler.jsonc or .dev.vars.example
npm run deploy              # build + remote D1 migrations + wrangler deploy (manual path; CI uses Workers Builds)
# Simulate inbound mail against `npm run dev` (the raw message must include a Message-ID header):
curl -X POST --data-binary @mail.eml "http://localhost:5173/cdn-cgi/handler/email?from=a@example.org&to=<address>"
```

Tooling gotchas:
- npm 12 blocks install scripts unless listed in `package.json#allowScripts`, which pins exact versions. After a dependency bump, `npm install` warns that `workerd`/`esbuild` scripts were blocked — run `npm install-scripts approve workerd esbuild` then `npm rebuild workerd esbuild`.
- `worker-configuration.d.ts` is generated but committed, because `npm run build` (also run by Workers Builds) type-checks against it. `cf-typegen` reads secret *names* from `.dev.vars.example` (not your local `.dev.vars`), so types are identical on every machine; a new secret must be added there.
- vue-i18n parses `@`, `{`, `}`, `|` in messages as syntax — never put email addresses or literal braces in `src/locales/*`; keep such sample data in the component.
- Local D1 state is keyed by `database_id`; after changing it, run `npm run db:migrate:local` again or every query fails with `no such table`.
- Stay on Vitest 4.x until `@cloudflare/vitest-plugin` is verified on a newer major. `@cloudflare/vitest-pool-workers` is the deprecated old name — don't reintroduce it.

## Architecture

**Service modes** (`SERVICE_MODE` var, read only as `getConfig(env).mode`; unset/invalid → `temporary`; this repo's own deployment is `personal`). Mode checks live in a few entry points only — keep it that way:
- `personal`: only `role = 'admin'` accounts sign in (`/login` answers 403 `admin_only`; `requireUser` ends other sessions with 401) and receive mail (`IngestLimits.adminOwnersOnly`); registration is always closed (`isRegistrationOpen`); no active-address quota or total cap (`MailboxLimits.quotaApplies = false`, `getQuota` → `limit: null`); manual local parts may be 1–32 chars and use reserved names (`isValidLocalPart(v, { personal: true })`); starring, catch-all and sending exist.
- `temporary`: the multi-user service; `isSendingEnabled()` is always false, and the sending, starring and catch-all endpoints answer 404.
- Client: `src/stores/mode.ts` (`isPersonal()`, loaded from `/api/settings/public` by the router guard before sign-in).

**One Worker, three entry points** (`worker/index.ts`):
- `fetch` → Hono app (`worker/app.ts`, mounted at `/api`). Static assets (the built Vue SPA) are served by Workers Static Assets *before* the Worker runs, except paths matching `assets.run_worker_first` (`/api/*`) in `wrangler.jsonc`. Unknown non-API paths fall back to `index.html` (`not_found_handling: single-page-application`), so client routes need no server code.
- `email` → `worker/email.ts`, invoked by Email Routing's catch-all rule. Catch-all routing alone accepts nothing. Pipeline: recipient must be printable ASCII → `findDeliveryTarget()` (`worker/repo/ingest.ts`) matches the lowercased envelope recipient exactly (or `local+tag@` → `local@` when that mailbox set `accept_subaddress`), accepting only an `active` mailbox of an `active` user (an admin in personal mode); in personal mode, if nothing matched, `findCatchAllTarget()` may return an address to create (see *Catch-all* below); every other case gets the single reason `REJECT_UNAVAILABLE` — never reveal which → cheap `ingestBlock()` pre-check → read only the first `INGEST_PARSE_WINDOW_KB` (256 KB) of the raw stream (with an R2 bucket and room in `RAW_MAIL_MAX_MB_PER_DAY`, `message.raw` is `tee()`d first; see *Originals in R2* below) → postal-mime with nesting/part/header limits (failures bounce with `REJECT_MALFORMED`, never throw) → `prepareMessage()` (`worker/lib/mail-content.ts`: byte-capped bodies, attachment metadata as JSON, display text stripped of bidi/control chars, `extractVerificationCode()` from `worker/lib/otp.ts`) → `storeMessage()`, a conditional INSERT that re-checks owner status, per-mailbox/per-user hourly caps (admins exempt) and the service-wide daily message/byte budget (`ingest_counters`, admins included), bumped in the same batch. All limits come from `INGEST_*` vars. Budgets exist because the project runs on the Workers/D1 **Free plan** (10 ms CPU per invocation, ~100k row writes/day, 500 MB); keep each delivery ≈7 row writes and well under 10 ms CPU. HTML bodies are stored raw and must only ever be rendered through the sandboxed viewer.

**Catch-all** (personal mode, migration `0013`): `domains.catch_all_user_id` (NULL = off) names the administrator who switched it on and owns every address it creates. `findCatchAllTarget()` accepts only a strictly valid local part (`isValidLocalPart` without options: 3–32, no `+`, no reserved name), an enabled domain whose owner is an active admin, and an address that is neither taken (in any status — a disabled address keeps bouncing) nor retired. `storeMessage()` then runs `INSERT OR IGNORE INTO mailboxes … auto_created = 1` carrying every gate of the message INSERT, in the same batch, so a created mailbox always gets its first message and a refused message leaves no address; if a concurrent first delivery created it, the message is delivered there once. Limits: `CATCH_ALL_MAX_PER_DAY` new addresses (counter `ingest_counters.auto_created`) and `CATCH_ALL_MAX_PER_ADDRESS_PER_HOUR` per auto-created address (both admin-overridable; SQL reads the override via `settingIntSql()`), and auto-created mailboxes together get at most half of each daily ingest budget (`catch_all_messages`/`catch_all_bytes`). Auto-created mailboxes get no admin exemption from these and don't count toward the manual daily creation cap. Refused creations bounce with `REJECT_UNAVAILABLE`.

**Originals in R2** (`MAIL_BUCKET`, optional; `worker/lib/raw-mail.ts`): after a successful parse, the other `tee()` branch is pumped by hand (workerd can't `pipeTo()` from a tee branch into another TransformStream) into a `FixedLengthStream(rawSize)` and `put` at `u/<userId>/<messageId>.eml`; the message id is generated before the put so `messages.raw_r2_key` is written in the same INSERT. Put failure → stored without original; INSERT refused → the object is deleted. The Worker never decodes attachments (CPU): `GET /api/messages/:id/raw` streams the object as `application/octet-stream` + `attachment`, and the client (`src/lib/original-mail.ts`, lazy `postal-mime`) extracts attachment content (saved as octet-stream Blobs) and `cid:` images (data: URIs substituted before DOMPurify). Every message deletion must remove its object: single deletes use `RETURNING raw_r2_key`, bulk deletes go through `deleteBatch(db, bucket, …)`. Code must keep working without the binding — read it only via `mailBucket(env)` (`worker/lib/config.ts`).
- `scheduled` → cron in `wrangler.jsonc#triggers` → `runCleanup()` (`worker/jobs/cleanup.ts`): deletes mail older than the effective retention (`MESSAGE_RETENTION_DAYS`, default 30, admin-overridable; 0 = forever) in 500-row batches, expired sessions, and ingest counters older than a week. Age-based deletes (retention, manual cleanup) skip starred mail in every mode (`is_starred`, migration `0012`, partial index `idx_messages_user_starred`; capped per user by `MAX_STARRED_MESSAGES` inside the UPDATE); purging a user deletes everything.

**Build/deploy shape**: `@cloudflare/vite-plugin` builds the client and the Worker together and writes `dist/postluma/wrangler.json` plus `.wrangler/deploy/config.json`, a redirect, so plain `wrangler deploy` and `wrangler d1 migrations apply` read the *built* config. Edit `wrangler.jsonc`, never the generated copy.

**Request pipeline** (`worker/app.ts`): `secureHeaders` → `Cache-Control: no-store` → `checkOrigin` (CSRF) → 64 KB `bodyLimit` → default-deny gate (`PUBLIC_ROUTES` set; everything else runs `requireUser`) → `/api/admin/*` additionally `requireAdmin` → route. Handlers signal failures by throwing `ApiError(status, code)`; `onError` serializes it as `{ error: code }`. Request bodies go through `parseJson(c, zodSchema)` from `worker/lib/request.ts`. Auth-sensitive endpoints call `enforceRateLimit` and `requireTurnstile`.

**Routes so far**: `/api/auth/*`, `/api/settings/public`, `/api/domains` (enabled domains), `/api/mailboxes` (list/create/get/patch — no DELETE by design), `/api/messages` (list/summary/get/patch/delete/mark-read — `worker/repo/messages.ts`; reading never mutates, the client PATCHes read state), `/api/admin/domains` (admin CRUD, plus `/:id/health`: MX lookup over Cloudflare DoH, `worker/lib/dns-health.ts`), `/api/outbox` (send/list/get/status — `worker/repo/outbox.ts`, Phase 9), `/api/admin/users` (list/action/quota/sending/message-count/purge-messages/delete — `worker/repo/admin-users.ts`), `/api/admin/sending` (switch, status, test send), `/api/admin/{settings,stats,audit,cleanup}` (`worker/routes/admin/system.ts`).

**Code layout**: `src/` is the Vue 3 SPA (alias `@` → `src`). `worker/` is server code: `routes/` (Hono sub-apps), `repo/` (all SQL), `middleware/`, `lib/` (crypto, password, cookies, request helpers). `shared/api.ts` holds the error-code list, API types and zod schemas imported by both sides (frontend imports it via relative path). Three TS projects: `tsconfig.app.json` (DOM, `src/` + `shared/`), `tsconfig.worker.json` (Workers types from `worker-configuration.d.ts`, `worker/` + `shared/` + `test/`), `tsconfig.node.json` (config files).

**Data model** (`migrations/0001_init.sql`; never edit an applied migration, add `000N_*.sql`):
- `users.status`: `pending → active | rejected`, `active ↔ banned`. Only `active` users may log in or receive mail. The first admin is `admin`, bootstrapped from the `ADMIN_INITIAL_PASSWORD` secret.
- `sessions.id` is SHA-256 of the cookie token; the raw token exists only in the cookie.
- `mailboxes.status` has exactly two values: `active` (receives mail) and `disabled` (rejects new mail, history still readable, can be re-enabled). Disabled mailboxes are listed on a separate page. There is **no mailbox delete feature** — don't add one. Only `active` mailboxes count toward the user's quota (so re-enabling must re-check quota).
- Addresses are never reusable: when a user account is deleted, its addresses go into `retired_addresses`; mailbox creation checks both `mailboxes.address` and `retired_addresses`, so no user can ever receive a previous owner's mail.
- `domains` (admin-managed) replaces any env-var domain list; a disabled domain blocks new mailboxes only. Each domain also needs an Email Routing catch-all in the Cloudflare dashboard.
- Mailbox writes enforce quota, enabled domain, retired-address and creation caps *inside* the conditional INSERT/UPDATE (`UNDER_QUOTA`, `UNDER_CREATION_LIMITS` in `worker/repo/mailboxes.ts`), so concurrent requests can't overshoot; `creationFailure()` only picks the error code afterwards. Stored addresses are always lowercase `local@domain` (local part via `normalizeLocalPart`, domains lowercased on creation, and DB triggers from migration `0002` reject anything else — note their `COLLATE BINARY`, since both columns are NOCASE). The email handler must match on the lowercased recipient.
- Effective quota = `users.mailbox_quota` ?? admin override `settings.default_mailbox_quota` ?? `DEFAULT_MAILBOX_QUOTA`, counting active mailboxes only (`effectiveQuotaSql`). Creation is also capped by `MAX_TOTAL_MAILBOXES` (any status) and `MAX_DAILY_MAILBOX_CREATIONS` (rolling 24 h); these stop create→disable loops from squatting never-reusable addresses.
- `messages.user_id` is denormalized from the mailbox so every user-facing query can filter `WHERE user_id = ?` directly.
- Mailbox `last_received_at` is not written by ingest (saves a row write per message); the API derives it with `MAX(received_at)`.
- **D1 read/write budget rules** (Free plan: 5M rows read, 100k written per day; review-measured): every query that runs per request or per poll must be index-bounded. Join `messages` to `mailboxes` with `CROSS JOIN` so `messages` stays the outer loop (`test/query-plans.test.ts` runs ANALYZE and fails on `SCAN m` / `MULTI-INDEX OR`); write cursors as row values `(a, b) < (?, ?)`; cap counts (`UNREAD_COUNT_CAP`), search windows (`SEARCH_WINDOW`), bulk updates (`MARK_READ_BATCH`); check ownership with a one-row `SELECT 1`, not the heavy `SELECT_MAILBOX`; polls send `known` so an unchanged inbox costs one seek. Every new partial index costs a write per insert — justify it.
- `audit_logs` records admin actions and auth failures. `settings` is a key/value table for admin-tunable config (default quota, retention, `registration_open`).
- Timestamps are epoch milliseconds (INTEGER). D1 enforces foreign keys; `ON DELETE CASCADE` is the cleanup path.

**Security invariants** (from PRD §6 — tenant isolation is the top priority; enforced in code review):
- Every non-auth `/api` route resolves the session and re-checks `users.status = 'active'` on each request (bans take effect immediately) — and, in personal mode, `role = 'admin'`, so switching a deployment to personal ends every other session at once. Admin routes additionally require `role = 'admin'`.
- Route handlers never call `env.DB` directly for user data. All mailbox/message/attachment access goes through `worker/repo/*` functions whose first argument is the session's `userId` and whose SQL always includes `user_id = ?`. A resource owned by someone else returns 404 (not 403) so ids can't be probed.
- Admins manage accounts, quotas, domains and settings, and see aggregate counts only. No admin endpoint returns mail content or users' addresses (product decision, not a TODO; `test/admin-users.test.ts` asserts it). Admin accounts can't be suspended or deleted through the API (`cannot_modify_admin`). Bulk deletions (retention cron, user purge, manual cleanup) go through `deleteBatch()` (`worker/repo/maintenance.ts`), which draws from one per-UTC-day budget `MAX_DELETES_PER_DAY` (~6 row writes per deleted message, shared 100k writes/day); responses carry `budgetExhausted`. Accounts must be banned before deletion. Admin retention overrides are capped at `maxRetentionDays` (INGEST_MAX_MB_PER_DAY × days ≤ 400 MB). Audit rows are batched with the change they record; failed logins are audited only for existing accounts, with no free text.
- Email ingestion derives `user_id` solely from the D1 mailbox row matched by exact lowercase recipient address — never from headers. No fuzzy matching. The only folding is opt-in per-mailbox subaddressing (`local+tag@` → `local@`, first `+`, migration `0007`); it is cross-tenant safe only because `LOCAL_PART_PATTERN` forbids `+` in created addresses — never relax that (personal mode relaxes only the length and the reserved names, for manual creation). `to_address` keeps the tagged recipient. The one other source of ownership is catch-all (personal mode): `domains.catch_all_user_id`, again a D1 row, and only for a strictly valid, untaken, unretired address (see *Catch-all*).
- State-changing requests require a same-origin `Origin` header (CSRF) in addition to `SameSite=Lax` cookies. Login rotates the session token; ban, reject and password change delete all of that user's sessions.
- Sessions are only ever created through `prepareSession()` (`worker/repo/sessions.ts`), whose INSERT is conditional on the user still having the verified password hash and `status='active'`. Run it in the same `db.batch()` as any status/password change, so a racing login can't outlive a ban or password change.
- Rate-limit keys must never be chosen by an unauthenticated caller alone (e.g. a per-username bucket) — that lets anyone lock a victim out. Login uses per-IP limits + Turnstile + PBKDF2 cost.
- Turnstile fails closed: a missing `TURNSTILE_SECRET_KEY` makes auth return 500 unless `TURNSTILE_DISABLED=true` (local dev/tests only, never in production). The siteverify `hostname` and `action` must match.
- The initial-admin bootstrap runs once per database (guarded by `settings.admin_bootstrapped`, written in the same batch). Never weaken this to "if no admin exists".
- Every new endpoint gets a cross-tenant test: user B requesting user A's resource must get 404 and must not mutate anything.
- Passwords: PBKDF2-SHA256 via WebCrypto, per-user salt, constant-time compare. New hashes use 20,000 iterations because the project runs on the Workers **Free plan** (10 ms CPU/request; 100k measured at ~11 ms). Each hash stores its own count, so raising `PBKDF2_ITERATIONS` (max 100,000) later keeps old hashes valid.
- Login/register: `AUTH_LIMITER` (Workers Rate Limiting binding) + Turnstile verification (`TURNSTILE_SECRET_KEY`).
- HTML mail is rendered only via `prepareMailHtml()` → `MailFrame.vue` (`src/lib/mail-html.ts`): DOMPurify, then a srcdoc carrying its own CSP (`img-src data:` until the user clicks “load images” for that message), inside an iframe sandbox with only `allow-popups allow-popups-to-escape-sandbox` (never `allow-scripts` / `allow-same-origin`). srcdoc frames inherit the parent CSP too, which is why `public/_headers` allows `img-src https:` — the frame's own CSP is the real restriction. Everything else from a message (subject, sender, snippet, filenames) is text-interpolated only; plain-text bodies go through `linkify()` + `TextBody.vue`. When verifying in a browser, check request *failure reasons*: Chromium reports CSP-blocked CSS images as requests that fail with `csp`, not as network traffic.

**Sending** (Phase 9, `docs/SENDING_PLAN.md`; personal mode only, off by default): `isSendingEnabled()` is false in temporary mode, so there the outbox, the admin sending routes, a domain's `canSend` and `/api/admin/users/:id/sending` all answer 404 and the client shows nothing. In personal mode two switches must be on — the service-wide one (`SENDING_ENABLED` var, admin override `settings.sending_enabled`) and `domains.can_send` (switching on asks the provider whether the domain is verified); the per-user `users.can_send` has no UI any more (only admins sign in, and admins can always send: `can_send = 1 OR role = 'admin'` everywhere), quotas still apply. The sender sees the sending UI even before any of their addresses can send; the compose form says why. With the service switch off, every `/api/outbox` route except `/status` is 404 and the client shows nothing (`src/stores/outbox.ts` → `canSend()`). `reserveSend()` inserts a `sending` row in one conditional INSERT (own active mailbox, both switches, per-user and service-wide rolling-24 h quotas counted from `sent_messages` rows capped at the quota, replied-to message owned by the user, `UNIQUE(user_id, idempotency_key)`), batched with a metadata-only `mail.send` audit row (recipient count, never addresses or content); the route then calls the provider (`worker/lib/mailer/`: `resend`, record-only `log` for dev/tests) and `finishSend()` records the result — rejected sends are refunded (`counted = 0`), timeouts/5xx are not. From is always the mailbox address; plain text only; subjects may not contain CR/LF; recipients are bare addresses (no display names), at most `SEND_MAX_RECIPIENTS`; reply threading uses the answered Message-ID only when it is a plain `<id>`. Sent mail follows retention in `runCleanup()`. Tests and e2e use `MAIL_PROVIDER=log`; Resend tests mock `fetch`.

**Secrets** (`wrangler secret put` in prod, `.dev.vars` locally; template in `.dev.vars.example`): `ADMIN_INITIAL_PASSWORD`, `TURNSTILE_SECRET_KEY`, optional `RESEND_API_KEY` (sending), plus dev-only `TURNSTILE_DISABLED`.

**Configuration** has three layers:
1. `wrangler.jsonc#vars` — deploy-time tunables (rate limits, ingest budgets, parse window, PBKDF2 cost, session TTL, defaults). Read **only** through `getConfig(env)` (`worker/lib/config.ts`), which validates ranges and falls back to defaults; pass the values into repo functions/SQL as bound parameters. `wrangler deploy` overwrites dashboard-edited vars, so the file is the source of truth. A new var needs an entry in `INT_VARS`/`getConfig`, a commented line in `wrangler.jsonc`, and `npm run cf-typegen` (run with `--strict-vars=false`, so vars are typed `string`).
2. `settings` table — only admin runtime overrides of product settings (`registration_open`, `default_mailbox_quota`, `retention_days`, and in personal mode `catch_all_max_per_day`, `catch_all_max_per_address_per_hour`; see `worker/repo/settings.ts`, where `settingIntSql()` lets SQL apply an override inline) plus internal flags. A missing row means "use the var". Never seed defaults here (migration `0004` removed the old seeds).
3. Domains live in their own table (admin-managed).
Tests override vars with `api(path, { env: { VAR: '…' } })` (runs the Hono app in-process) or by passing `{ ...env, VAR: '…' }` to `handleEmail` / `getConfig`.

**Frontend**: Naive UI for components, vue-i18n for text. Session state is `src/stores/session.ts` (no Pinia); the service mode is `src/stores/mode.ts` (`isPersonal()` gates the register link, the Users tab, the registration/quota settings, the sending card, stars and the Starred filter, the catch-all switch and settings, and the "Auto-created" tag); `src/stores/inbox.ts` holds the unread badge and polls `/api/messages/summary` every 30 s only while the tab is visible (D1 read budget) — views watch `inbox.latestReceivedAt` and pull just the new rows with `since`; the router guard in `src/router/index.ts` loads it once and enforces `meta.public` / `meta.admin`. `src/api/client.ts` throws `ApiRequestError(status, code)` and triggers a global redirect to login on any 401 outside `/api/auth/*`. Post-login redirects go through `safeRedirect()`. Visual tokens live in `src/styles/main.css` (`--pl-*`) and `src/theme.ts` (Naive overrides) — direction B (“signal desk”): light by default, ink-ground dark theme, Schibsted Grotesk + JetBrains Mono self-hosted via @fontsource (CSP `font-src 'self'`). Amber (`--pl-signal`, `--pl-mark`, `--pl-code-bg`) is reserved for verification codes not yet copied and verification links not yet opened: copying a code (`useCopyCode`, or `CodeChip` with `message`) or opening a link (`LinkChip`, `markHandled`) marks its message read and the highlight goes away. Verification links are detected at delivery by `worker/lib/magic-link.ts` (https only, no credentials; table-driven in `test/magic-link.test.ts`) and only ever rendered as anchors after `safeLink()` (`src/lib/links.ts`) with `rel="noopener noreferrer nofollow"`; the message view itself shows no code or link card. Buttons outside Naive use the shared `.pl-btn` / `.pl-btn.primary` (ink) / `.pl-btn.quiet` classes; navigation underlines are ink. The home page's “current address” (`src/stores/current.ts`, per user in localStorage) is whatever was last created (`useCreateMailbox`: create → copy → make current), copied or picked, falling back to the newest address made by hand (`HomeView` fetches it by id, or with `GET /api/mailboxes?manual=1`, when it isn't on the list's first page of 50), so catch-all never makes an address current on its own; only a user with no address made by hand falls back to the newest one; its mail opens in a dialog on the home page (`MessageDetail` is shared with the inbox drawer), and the address list marks unread mail with a green dot only. Desktop uses a top navigation, phones a bottom tab bar (`src/layouts/AppLayout.vue`); views that fill the viewport subtract `--pl-chrome`. Views react to new mail by watching `inbox.arrivals` (not `latestReceivedAt`, which starts null for users without mail); `boostPolling()` speeds polls to 10 s for a while after creating an address. Initial locales are `zh-CN` and `en`; adding one (e.g. `ja`) should only need a new `src/locales/<lang>.ts` plus registering the matching Naive UI locale and date locale. No user-visible string is hard-coded in components. The API returns stable error codes (e.g. `mailbox_quota_exceeded`), and the frontend translates them.

## Testing

Tests run inside workerd via `cloudflareTest()` in `vitest.config.ts`, reading bindings from `wrangler.jsonc`. `test/apply-migrations.ts` runs `reset()` and re-applies `migrations/` before **every test** — the plugin does not isolate storage on its own, so never rely on data from another test. Tests live in `test/*.test.ts`; cross-tenant matrices go in `test/isolation/`. Use `api()` / `createUser()` / `login()` from `test/helpers.ts` for HTTP-level tests (it sets a matching `Origin` and a unique `cf-connecting-ip` per call so rate-limit buckets don't collide) and `env.DB` for direct assertions. In tests `ADMIN_INITIAL_PASSWORD` is `test-admin-password` and Turnstile is disabled (see `vitest.config.ts`). To test the email handler, build a message with `mime()` and wrap it with `emailStub()` from `test/helpers.ts`, then call `handleEmail(stub, env, createExecutionContext())`; `stub.rejected` holds any `setReject()` reason. `vitest.config.ts` pins `SERVICE_MODE=temporary`, whatever `wrangler.jsonc` says; personal-mode tests pass `env: { SERVICE_MODE: 'personal' }` to `api()` (or `{ ...env, SERVICE_MODE: 'personal' }` to `handleEmail`) and sign in as admins (`createUser(name, { role: 'admin' })`), (`test/personal-mode.test.ts`, `test/starring.test.ts`, `test/catch-all.test.ts`; temporary-only behaviour in `test/temporary-mode.test.ts`), with two admins for cross-tenant cases (`test/isolation/catch-all.test.ts`, `test/isolation/outbox.test.ts`). Sender authentication (`worker/lib/sender-auth.ts`, migration `0010`) trusts only the topmost `ARC-Authentication-Results` header with authserv-id `mx.cloudflare.net` — never `Authentication-Results`, never a lower header — and is recorded only when the `SENDER_AUTH_HINTS` var is `true` (off by default until a real delivered message confirms the header; `test/sender-auth.test.ts` holds the forgery cases). Verification-code and verification-link heuristics are table-driven in `test/otp.test.ts` and `test/magic-link.test.ts` — add a row for every new false positive/negative.

Browser tests live in `e2e/*.spec.ts` (Playwright, own `tsconfig.e2e.json` with DOM types). There are two projects, each with its own dev server and throwaway state: `temporary` (port 5188, `.wrangler/e2e`) and `personal` (port 5189, `.wrangler/e2e-personal`, runs `*.personal.spec.ts` only). `POSTLUMA_E2E=1` + `POSTLUMA_E2E_MODE` make `vite.config.ts` pick the state directory, set `SERVICE_MODE` and `TURNSTILE_DISABLED`; each web server command wipes and re-migrates its state per run. `e2e/helpers.ts` picks the project's server and database from `test.info()`; in temporary mode it registers users via the API and approves them with `wrangler d1 execute`, in personal mode (no sign-up) it inserts accounts with a PBKDF2 hash in the stored format; mail goes through `/cdn-cgi/handler/email`. The personal database is shared by its specs: undo switches you turn on (e.g. catch-all). Changes to mail rendering must keep `e2e/mail-rendering.spec.ts` green.

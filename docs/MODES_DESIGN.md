# 部署模式：个人邮箱 / 临时邮箱（设计）

> 状态：已确认（2026-11-02）。实施计划见 [MODES_PLAN.md](MODES_PLAN.md)，进度记在 `docs/DEV_PLAN.md` 的 Phase 10。
> 界面以第 4 节的描述为准（讨论时用的示意图没有放进仓库）。

## 1. 为什么做

- PostLuma 最初是给几个好友用的临时邮箱。实际上只有你一个人在用，而且你想把它当正式邮箱，但主要用途仍然是**收信**。
- 选 Cloudflare 的原因：不用自己维护 VPS（nginx、Linux 内核漏洞都要追着打补丁），省心又便宜。
- 现在的问题是定位乱：临时邮箱的规则（随机地址、到期自动删除、多人审核）和正式邮箱的需要（重要邮件留着、发信）混在一起，后加的发信功能让它变得四不像。
- 解决办法：**部署时选一种模式**。还是同一套代码，模式决定有哪些功能。你自己的部署用"个人邮箱"；别人从 GitHub 部署时，可以选"临时邮箱"。

## 2. 两种模式一览

| | 个人邮箱 `personal` | 临时邮箱 `temporary` |
|---|---|---|
| 谁能用 | 只有管理员账号（你的部署里就是 `admin`） | 注册后由管理员审核的多个用户 |
| 注册入口 | 没有 | 有（管理员可以关闭） |
| 后台"用户"页 | 没有 | 有 |
| 地址配额 | 不限数量（每天手动新建的上限保留） | 现在的规则 |
| 手动建地址 | 可以用保留前缀（contact、info、admin 等），最短 1 位 | 现在的规则：3–32 位，不能用保留前缀 |
| 收藏邮件 | 有 | 没有 |
| catch-all 自动建地址 | 有，按域名开关 | 没有 |
| 发信 | 有，默认关闭 | 没有 |
| 随机地址、验证码、验证链接、自动清理、R2 原件 | 有 | 有 |

## 3. 目标、不做的事、算失败的情况

**目标**
- 用一个部署配置项选择模式。改完重新部署就生效，不需要迁移数据。
- 你的部署切到个人模式后，admin 照常登录，现有的地址、邮件、发信都在。
- 个人模式新增两项功能：收藏邮件、catch-all 自动建地址。
- 临时模式去掉发信，回到纯粹的临时邮箱。
- 界面保持现在的风格，只做示意图里那几处小改动。

**不做**
- 不做完整的邮件客户端：没有文件夹或标签、IMAP/SMTP、通讯录、签名、HTML 写信、附件发送。
- 不收藏已发送的邮件，也不做"所有邮件永久保存"。
- 地址仍然只能停用、不能删除。
- 不在后台运行时切换模式，只能改部署配置。

**算失败的情况**（即使功能都能跑）
- 切换模式导致数据丢失。
- 为了两种模式到处加判断，代码变乱。模式判断必须集中在少数几个入口。
- 削弱现有的安全规则：租户隔离、收信只认信封收件人、地址永不复用、HTML 沙箱。
- 超出 Workers / D1 免费版的额度：每次调用 10 ms CPU、每天 10 万行写入、500 MB 存储。

## 4. 已经确定的（你定的）

1. 部署时选模式：个人邮箱或临时邮箱，按所选模式的配置部署。
2. 个人模式只有管理员使用。你平时就用 `admin` 收信，所以地址和邮件不需要迁移。
3. **收藏**：邮件行右侧有星标，点一下收藏、再点取消；邮件详情的工具栏里也有星标；收件箱筛选多一个"收藏"。收藏的邮件（连同 R2 里的原件）不会被自动清理，详情里会注明"已收藏，不会被自动清理"。
4. **catch-all**：在后台"收信域名"里按域名开关。发到这个域名任意地址的第一封信，会自动建好这个地址。自动建的地址直接放进"使用中"，带"自动创建"标签。不想要的地址点"停用"，之后发到它的信会被退回（示意图里的方案 A）。
5. 自动清理默认保留，因为 D1 和 R2 的免费容量有限。
6. 发信只在个人模式里有，默认关闭，开启方式和现在一样。
7. 临时模式就是现在的样子，但去掉发信，也没有收藏和 catch-all。
8. 界面：个人模式的登录页没有"注册"；后台没有"用户"页；系统设置里没有"开放注册"和"默认地址配额"。其他页面不变。
9. 个人模式下，手动建地址不受保留前缀（contact、info、admin、postmaster 等）和"最短 3 位"的限制，`me@`、`contact@` 都可以建；仍然不能含 `+`，最长 32 位。catch-all 照旧按严格规则，不会自动建这些地址，想用就手动建。
10. 个人模式没有"每个用户每小时"的收信上限（只有你一个人）。自动建的地址每个每小时最多收 10 封，默认值来自 `CATCH_ALL_MAX_PER_ADDRESS_PER_HOUR`；手动建的地址和现在一样不限。
11. catch-all 的两个上限（每天最多自动建几个地址、自动建的地址每个每小时最多收几封）都可以在后台"系统设置"里调整，也能恢复默认。这一块只在个人模式出现。

| 3 | 个人模式下，非管理员账号不删除，但不能登录，已有的登录立即失效，它们的地址也不再收信。切回临时模式后恢复。密码正确但不是管理员时，提示"这个站点是个人邮箱，只有管理员能登录"。 | 不丢数据；只有输对密码才会看到这个提示，所以不会泄露账号是否存在。 |
| 4 | 个人模式下，管理员不受"使用中地址配额"和"地址总数上限"限制；手动新建地址的每日上限保留，只统计手动建的地址。 | 配额和总数上限是为了防止多个用户抢占地址，个人模式没有这个问题。如果保留总数上限（默认 100），catch-all 很快就会撞上。 |
| 5 | 收藏有上限：每人最多 500 封（`MAX_STARRED_MESSAGES`，可调）。达到上限后再收藏会失败并提示。 | 收藏的邮件会一直占用 D1 的 500 MB，而保留期的上限正是按这 500 MB 算的。 |
| 6 | 收藏的邮件在两种模式下都不会被自动清理。后台的"立即清理 N 天前的邮件"也会跳过收藏。删除用户时，收藏的邮件照样删除。 | 从个人模式切回临时模式时，已经收藏的邮件不会被删（临时模式只是没有收藏入口）。 |
| 7 | catch-all 全站每天最多自动建 10 个地址（按 UTC 日计）。默认值来自 `CATCH_ALL_MAX_PER_DAY`，管理员可以在系统设置里调整。超过以后，当天发到新地址的信都退回。 | 垃圾邮件会撞上各种随机地址；地址又不能删除，必须控制增长速度。 |
| 8 | catch-all 不会自动建这些地址：带 `+` 的、不符合地址规则的（3–32 位，限定字符）、保留前缀（如 postmaster）、以前退役过的、域名已停用的。已经存在的地址（包括已停用的）不会被重新创建，停用的照样退信。`name+tag@` 和现在一样，只在 `name@` 存在并且开启了 +别名 时投递，不会因为 catch-all 而新建地址。 | 守住"地址永不复用"和"创建的地址不含 `+`"这两条安全规则（`+` 规则是 +别名 不跨用户的前提）。 |
| 9 | 自动建出来的地址属于在这个域名上打开 catch-all 的那个管理员。归属只看收件地址和域名配置，不看任何邮件头。 | 沿用"归属只来自 D1"的规则；即使有多个管理员，归属也是确定的。 |
| 10 | 自动建的地址合计每天最多用掉全站每日收信额度的一半（条数和字节分别算）。超过后，当天发到自动建地址的信都退回；手动建的地址不受影响。 | 全站额度用完以后，正常邮件会被直接退回，发件方不会重试。这条保证垃圾邮件再多，正常邮件也还有一半额度。 |
| 11 | catch-all 拒收时统一用 `Mailbox unavailable` 作为退信理由。 | 和现在一样，不透露是哪条规则拦下的。 |
| 12 | 个人模式里没有按用户的"允许发信"开关（只有管理员能登录，而管理员本来就能发信）。发信额度照旧。 | 这个开关在"用户"页里，个人模式没有这个页面。 |
| 13 | 首页的"当前地址"在没有记住的地址时，回退到最新的**手动创建**的地址，不会跳到自动创建的地址上。 | 不能让一个垃圾地址突然变成"当前地址"。 |
| 14 | 临时模式下，收藏、catch-all、发信相关的接口一律返回 404，和现在发信总开关关闭时一样。 | 接口和界面保持一致，不留半开的功能。 |
| 15 | 个人模式的首页只显示地址数量，不显示"4 / 10"这样的配额。 | 个人模式没有配额。 |
| 16 | 自动建的地址和触发它的第一封信在同一个事务里写入。信没存下来（超出额度、解析失败等），地址也不建。 | 解析失败的垃圾邮件不该留下地址，也不该占用每天 10 个的名额。 |

## 6. 必须遵守的约束

- **免费版额度**
  - 每封信仍约 7 次 D1 行写入；catch-all 新建一个地址额外约 5 次写入，受每日上限约束。
  - 收藏用部分索引，只在收藏或取消收藏时写入，普通收信不受影响。
  - 收信的 CPU 不能明显增加：只有在收件地址没匹配上时，catch-all 才多查一次。
- **安全规则全部保留**（见 CLAUDE.md）
  - 收信归属只来自 D1 里的地址行和域名配置。
  - 地址永不复用；`LOCAL_PART_PATTERN` 不允许 `+`。
  - 所有限制都在条件 INSERT/UPDATE 里原子检查，并发也不会超限。
  - 按请求或轮询执行的查询都要走索引，新查询加进查询计划测试。
  - 每个新接口都要有跨用户测试：用户 B 拿不到、也改不了用户 A 的东西。
- **个人模式里的跨用户隔离**：只有管理员能登录，但数据仍按 `user_id` 隔离。测试用两个管理员账号互相验证。
- **迁移只追加**：只加列（带默认值）和索引。旧代码能在新表结构上运行，所以可以用 `git revert` 单步回滚。
- **模式判断集中在少数入口**
  - 后端：`getConfig(env).mode`，只在登录/会话、收信、发信开关，以及收藏和 catch-all 的路由里判断。
  - 前端：一个 mode 状态，从 `/api/settings/public` 读取（登录前就需要知道是否显示"注册"）。
- **测试默认跑临时模式**：在 `vitest.config.ts` 里固定 `SERVICE_MODE=temporary`，这样仓库配置改成 personal 后，现有测试不会全部换了语义；个人模式的测试单独覆盖这个变量。e2e 两种模式都要能跑。

## 7. 你的部署怎么切换

1. 开发过程中，仓库配置已经改成 `personal`（实施计划 Task 4）。全部完成、测试通过后再推送。
2. 部署时会自动执行新迁移（只加列和索引）。
3. 用 admin 登录，确认地址、邮件、发信都在；后台没有"用户"页；登录页没有"注册"。
4. 在"收信域名"里，给需要的域名打开 catch-all。

回退：把 `SERVICE_MODE` 改回 `temporary` 再部署，数据不受影响。

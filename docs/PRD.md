# 产品需求文档（PRD）

**项目名称：** PostLuma  
**产品定位：** 部署在 Cloudflare 上的轻量邮箱，部署时二选一：自己用的个人邮箱，或给少量受信任用户用的临时邮箱。

> 本文描述产品现状（2026-11-06）。两种模式的取舍见 [MODES_DESIGN.md](MODES_DESIGN.md)，具体决策见 [DEV_PLAN.md](DEV_PLAN.md) 和 [QUESTIONS.md](QUESTIONS.md)。

## 1. 产品概述

PostLuma 基于 Cloudflare Workers、Email Routing 和 D1 构建，无需 VPS。部署时用 `SERVICE_MODE` 选择模式：

- **个人邮箱 `personal`**：只有管理员使用。地址不限数量，可以用 `me@` 这类短地址和保留前缀；支持收藏邮件、catch-all 自动建地址和可选的发信。
- **临时邮箱 `temporary`**：用户自主注册，管理员审核通过后使用。地址有配额，不能发信。

两种模式的核心用法相同：创建地址，用于网站注册、接收验证码；历史邮件在保留期内可以随时查看。

## 2. 核心功能

### 2.1 用户系统
- 初始管理员账号为 `admin`，使用密码登录。
- 临时邮箱模式：用户可自主注册，默认状态为 `pending`，管理员审核通过后才能登录；管理员可以通过、拒绝、封禁和解封用户，也可以关闭注册。
- 个人邮箱模式：只有管理员账号能登录和收信，没有注册入口。
- 用户之间的数据完全隔离，管理员也看不到别人的邮件内容。

### 2.2 地址管理
- 一键生成随机地址，自动复制。
- 支持自定义地址前缀。
- 支持创建多个地址，每个用户拥有独立的地址列表。
- 支持设置备注、复制地址、搜索地址，以及按地址开启 `+别名`。
- 支持停用和重新启用。**不提供删除**：地址永不复用，停用的地址仍可查看历史邮件。
- 个人邮箱模式可以按域名打开 catch-all：发到新地址的第一封信会自动建好这个地址。

### 2.3 邮件
- 支持接收邮件，并且正确渲染；HTML 邮件在沙箱中显示，远程图片默认不加载。
- 自动识别并突出显示验证码和验证链接，支持一键复制、一键打开。
- 提供全局收件箱，集中显示所有使用中地址的邮件。
- 支持查看单个地址的历史邮件，包括已停用的地址。
- 支持邮件搜索、删除和已读状态。
- 原始邮件可选保存到 R2，用于下载附件、显示内嵌图片和查看完整正文。
- 邮件按保留期自动清理（默认 30 天）。个人邮箱模式可以收藏邮件，收藏的邮件不会被自动清理。
- 个人邮箱模式可选开启发信：用自己的地址写信和回复，只发纯文本；发出的邮件在发件箱查看。

### 2.4 管理后台
- 管理收信域名，检查 MX 是否指向 Cloudflare Email Routing。
- 查看系统使用统计和操作记录。
- 配置邮件保留期，手动清理旧邮件。
- 临时邮箱模式：用户申请审核、封禁与解封，设置用户地址配额，开关注册。
- 个人邮箱模式：配置 catch-all 上限和发信开关。

## 3. 地址状态

| 状态 | 接收新邮件 | 查看历史 |
|---|---|---|
| 使用中 | 是 | 是 |
| 已停用 | 否 | 是 |

## 4. 页面设计

采用简洁的响应式界面：桌面使用顶部导航，手机使用底部标签栏。

**用户端**
- 登录页面；临时邮箱模式还有注册页面
- 首页：一键创建地址、当前地址的最新邮件、验证码展示
- 收件箱：全部邮件、按地址筛选、邮件详情
- 发件箱：发出的邮件（个人邮箱模式开启发信后才有）
- 地址：地址列表、备注、状态操作
- 账户设置

**管理员端**
- 收信域名
- 系统设置、使用统计、操作记录
- 用户审核与配额设置（临时邮箱模式）

## 5. 技术架构

| 组件 | 技术 |
|---|---|
| 前后端 | Cloudflare Workers + Vue |
| 邮件接收 | Cloudflare Email Routing |
| 邮件处理 | Email Worker |
| 数据存储 | Cloudflare D1 |
| 原始邮件存储 | Cloudflare R2（可选） |
| 发信 | Resend（可选，个人邮箱模式） |
| 用户认证 | 密码哈希 + 安全 Session |
| 安全防护 | Cloudflare Turnstile + 限流 |

**邮件处理流程：**

1. 域名启用 Cloudflare Email Routing Catch-all，指向 Email Worker。
2. Worker 根据收件地址查询 D1。
3. 地址存在、处于使用中，且所属用户已激活 → 接收并保存。
4. 地址不存在、已停用或用户被封禁 → `setReject()` 拒收。个人邮箱模式下，打开了 catch-all 的域名会先判断能否自动建这个地址，能建才接收。
5. 用户登录后只能读取自己地址的邮件。

Catch-all 路由仅用于转发，不代表接受任意地址。

## 6. 安全要求

- 所有业务接口必须验证用户身份及账户状态。
- 地址、邮件查询必须校验资源所有权。
- 密码使用安全哈希算法存储，不保存明文。
- 管理操作仅允许管理员执行。
- 登录与注册接口启用防暴力破解、限流。
- HTML 邮件必须经过安全过滤，禁止执行脚本及默认加载远程跟踪资源。
- 邮件和账户删除应提供明确的数据清理机制。

## 7. 产品目标

以最低部署与维护成本，提供一个**简单、安全、可长期使用的邮箱**：自己用，或者给少量受信任的人用。

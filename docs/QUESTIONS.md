## Phase 2：邮箱管理

### Q1. 域名管理提前到了 Phase 2
**当前做法**：管理后台新增“收信域名”页，可以添加、启用/停用、删除域名。只有从未有地址使用过的域名才能删除。原计划这部分在 Phase 5 做，但没有域名就无法创建邮箱，Phase 2 无法端到端使用，所以提前做了最小版本。
**需要你确认**：无需决定，知会一下。用户管理和系统设置仍在 Phase 5。

### Q2. 随机地址的格式
**当前做法**：10 位，由小写字母和数字组成，去掉了易混淆的 i、l、o、0、1，首位一定是字母，例如 `k7mq2hx9ta@你的域名`，约 49 位随机熵。
**备选**：单词组合，例如 `quiet.fern42`，更好记，但更容易被猜到。
**需要你确认**：保持现状，还是改为单词组合？

### Q3. 停用域名的影响范围
**当前做法**：停用域名后，用户不能再在这个域名下**新建**地址；该域名下已有的地址照常收信。
**备选**：停用域名后，该域名下所有地址一并拒收。
**需要你确认**：哪一种？此项影响 Phase 3 的收信逻辑。

### Q4. 保留前缀
**当前做法**：以下前缀不允许用户使用：`abuse admin administrator hostmaster mailer-daemon noc no-reply noreply postmaster root security support webmaster`。
**需要你确认**：是否还要增加，例如 `info`、`contact`、`billing`？

### Q5. 自定义前缀规则
**当前做法**：3–32 位小写字母或数字；中间可以用 `.`、`_`、`-`，但不能出现在首尾，也不能连续出现；不支持 `+`（不做子地址）；输入的大写字母会自动转为小写。
**需要你确认**：长度范围是否合适？

### Q6. 备注长度
**当前做法**：最多 200 个字符。
**需要你确认**：无特别需要可忽略。

### Q7. 首页内容
**当前做法**：首页显示问候语、一键创建面板，以及最近 5 个使用中的地址。“最新邮件”和“验证码展示”等 Phase 4 有了邮件数据后再加。
**需要你确认**：无需决定，知会一下。

### Q10. 防止“创建→停用→再创建”无限占用地址（安全复审发现，已按默认值处理）
**背景**：你定的规则是“停用的地址不占配额”。地址又永不复用、也不能删除，于是有人可以用脚本反复执行“创建→停用”，无限占用地址（例如把常见名字全部抢注），数据库也会无限增长。复审时用配额 1 实测拿到了 8 个地址。
**当前做法**：保留你的规则（停用不占“使用中”配额），另加两道独立上限，都存在 `settings` 表中（migration `0002`），后续可在管理后台调整：
- 每个用户的地址总数（含已停用）上限：**100**
- 每个用户 24 小时内最多新建：**30** 个
**需要你确认**：这两个默认值是否合适？

### Q11. 复审发现的其他小问题（已修复，知会一下）
- 数据库层强制地址和域名为小写，保证 Phase 3 收信时精确匹配。
- 备注中的控制字符和双向文本覆盖字符会被过滤，防止视觉欺骗。
- 域名最长 221 个字符，保证完整地址不超过 RFC 5321 的 254 字符上限；支持 `xn--` 开头的 punycode 顶级域名。
- 域名操作的审计日志中记录了域名本身。
- 新增未读邮件的部分索引，为 Phase 4 做准备。
- “用户注册时可以探测某个自定义地址是否已被占用”：共享地址空间必然存在这一点，已由上面的 24 小时创建上限限速，接受。

## 部署相关

### Q8. “推送到云端”的理解
**当前做法**：我把代码推送到了 GitHub 远程仓库 `origin`（`git@github.com:ZeyuZuo/postluma.git`）的 `main` 分支，**没有**部署到 Cloudflare。
如果仓库已在 Workers & Pages 中接入了 Git 自动构建，推送会触发构建。但 `wrangler.jsonc` 里的 `database_id` 还是全 0 占位值，部署会失败。
首次部署需要你操作（步骤见 `docs/DEV_PLAN.md` Phase 6）：
1. 运行 `npx wrangler d1 create postluma`，把输出的 id 填入 `wrangler.jsonc`。
2. 在控制台设置 Secret：`ADMIN_INITIAL_PASSWORD`、`TURNSTILE_SECRET_KEY`；设置构建变量 `VITE_TURNSTILE_SITE_KEY`。
3. 在 Email Routing 中设置 Catch-all → Worker。

**需要你确认**：如果你本来想要的是直接部署到 Cloudflare，下次可以先运行 `npx wrangler login`，并把 D1 的 id 告诉我，我来完成部署。

### Q9. Workers 免费版 CPU 限制（沿用 Phase 1 的风险）
**当前做法**：登录时的 PBKDF2 计算大约需要几十毫秒 CPU，而免费版每个请求只有 10 ms。
**需要你确认**：你打算用免费版还是付费版（Workers Paid，5 美元/月）？如果用免费版，上线后需要实测，必要时降低迭代次数。

# 发信功能开发计划（草案，待确认）

> 状态：9.1–9.6 已完成（2026-10-21），9.7 待升级 Workers 付费版后再做。进度见 `docs/DEV_PLAN.md` Phase 9。
> 这会推翻 `DEV_PLAN.md`“本期不做”里的“发信和回复”和 README 的“不发信”，所以默认关闭，并且所有限制都在服务端强制执行。

## 1. 一句话

管理员在后台打开总开关，选好发信服务（Resend 或 Cloudflare），再勾选哪些域名能发、哪些用户能发。被允许的用户可以**用自己的地址**回复邮件或写新邮件。总开关关闭时，界面上看不到任何发信相关的东西，和现在完全一样。

## 2. 两个服务商的现状（2026-10 查证）

| | Resend | Cloudflare Email Sending |
|---|---|---|
| 状态 | 正式服务 | **Beta** |
| 免费额度 | 每天 100 封、每月 3,000 封、1 个域名 | 发给“账户里已验证的目标地址”免费；**发给任意收件人需要 Workers 付费版** |
| 接入方式 | `POST https://api.resend.com/emails`，`Authorization: Bearer` | Worker 绑定 `send_email`，`env.EMAIL.send({...})` |
| 发件域名 | 在 Resend 后台验证域名（加 DKIM/SPF 记录，通常用 `send.` 子域，不影响现在的收信 MX） | 域名需在 Email Service 中完成接入 |
| 单封限制 | 最多 50 个收件人，附件总计 40 MB | 最多 50 个收件人，整封 ≤ 5 MiB |
| 密钥 | Worker Secret `RESEND_API_KEY` | 无密钥，靠绑定 |

**结论**：项目在 Workers 免费版上，Cloudflare 发信目前只能发给自己验证过的地址，实际用处不大。**先做 Resend**，Cloudflare 作为第二个服务商留好接口，升级付费版后再接。

## 3. 使用逻辑

### 3.1 三层开关（全部默认关闭）

1. **总开关**（管理后台 → 系统设置 → 发信）：关闭时，所有发信接口返回 404，前端不显示任何发信入口。
2. **域名**（管理后台 → 收信域名）：每个域名多一个“可发信”开关。只有在服务商那边验证过的域名才应打开；打开时后台用服务商 API 校验一次，没验证就打不开。
3. **用户**（管理后台 → 用户）：每个用户多一个“允许发信”开关和每日额度。默认不允许。

> 为什么要第 3 层：临时邮箱最大的风险是被拿去发垃圾邮件或钓鱼，域名一旦被列入黑名单，**收信**也会受影响。只让管理员信任的人发信，是最便宜的防线。

### 3.2 谁、用什么地址、发给谁

- **发件人只能是自己的、使用中的地址**，且该地址的域名开启了“可发信”。不能填任意 From，不能用别人的地址，已停用的地址不能发。
- **收件人**：每封最多 5 个（可调），不支持密送（BCC），防止群发。
- **内容**：第一版只发**纯文本**（HTML 邮件容易被用来做钓鱼页面，也更容易进垃圾箱）。附件放到后续版本。
- **回复**：自动带上 `In-Reply-To` / `References`，主题加 “Re:”，正文引用原文，对方邮箱里会显示成同一个会话。

### 3.3 界面（只在“总开关开 + 你被允许发信”时出现）

| 页面 | 变化 |
|---|---|
| 收件箱 | 工具栏多一个“写邮件”按钮；筛选多一个“已发送” |
| 邮件详情（收件箱抽屉和首页弹窗共用） | 工具栏多一个“回复”图标，点开在同一个面板里显示回复框 |
| 写信面板 | 发件地址（下拉，只列可发信的地址，默认当前地址）、收件人、主题、正文；底部显示“今天还能发 N 封” |
| 首页 | **不变**。首页专注收验证码，不放发信入口 |
| 地址页 | 可发信的地址旁加一个小标记 |
| 管理后台 | 系统设置加“发信”区块（总开关、服务商、配置状态、全站每日上限、给自己发一封测试信）；域名加“可发信”开关；用户加“允许发信”和额度 |

总开关关闭或用户没权限时，上面这些一个都不出现。前端只看一个字段：`/api/auth/me` 返回的 `canSend`。

### 3.4 已发送的邮件

- 存在新表 `sent_messages`，和收到的邮件一样按 `user_id` 隔离，管理员看不到内容。
- 在收件箱“已发送”里能看到，状态是“已发送 / 失败（原因）”。
- 和收信共用保留期，旧邮件由每日清理删除，计入同一个删除额度。

## 4. 限制与安全（服务端强制）

| 规则 | 默认值 | 做法 |
|---|---|---|
| 每用户每日上限 | 20 封 | 和收信一样，在条件 INSERT 里检查，并发也不会超 |
| 全站每日上限 | 100 封（= Resend 免费额度） | 同上；接近上限时管理后台提示 |
| 每封收件人数 | 5 | zod 校验 |
| 正文大小 | 64 KB 纯文本 | zod + 字节检查 |
| 封禁立即生效 | — | 沿用每次请求重新检查 `users.status` |
| 审计 | 每次发信记一条 | 只记用户、发件地址、收件人**数量**、结果；不记收件人和内容（管理员不看内容） |
| 密钥 | — | `RESEND_API_KEY` 只用 Worker Secret，不进数据库、不进前端；后台只显示“已配置 / 未配置” |
| 失败处理 | — | 先写一条“发送中”记录并占用额度，再调服务商；服务商拒绝时标记失败并退还额度，网络超时不退（防止重复发） |
| 幂等 | — | 每次请求带客户端生成的 ID，作为 Resend 的 `Idempotency-Key`，双击不会发两封 |

每个新接口都要有跨用户测试：用户 B 不能用 A 的地址发信，也看不到 A 的已发送邮件。
